# Product Page

Responsive product page built from the Figma design as part of the Black Lemon frontend coding test.

## Getting started

Requirements: Node.js 18+

```bash
npm install
npm start          # dev server → http://localhost:1234/product.html
npm run build      # production build → dist/
npx serve dist     # preview the build → http://localhost:3000/product
```

## Tech stack

- **Parcel** – bundling, dev server, image optimisation
- **SCSS** (Dart Sass, `@use` / `@forward` modules)
- **Vanilla JavaScript** (ES modules)
- No frameworks or UI libraries

## Project structure

```
src/
├── pages/            # One HTML file per page – each is a Parcel entry
├── styles/
│   ├── abstracts/    # Variables, mixins (no CSS output)
│   ├── base/         # Reset, typography, utilities
│   ├── components/   # Reusable blocks (button, carousel, accordion…)
│   ├── layout/       # Container, header
│   ├── pages/        # Page-specific entry stylesheets
│   └── main.scss     # Shared entry stylesheet
├── scripts/
│   ├── components/   # Reusable modules (cart, carousel, accordion…)
│   ├── layout/       # Header / mobile menu
│   ├── pages/        # One entry script per page
│   └── common.js     # Code shared by every page
└── assets/           # Images and icons exported from Figma
static/               # Copied as-is to dist/ (robots.txt)
```

The structure is set up for a site with many pages. A new page only needs an HTML file in `src/pages/`, an optional stylesheet in `styles/pages/` and an entry script that imports `common.js` plus the components it uses.

## Key decisions

- **Mobile-first SCSS** with a single `mq()` breakpoint mixin and design tokens taken from Figma (colors, fonts, spacing).
- **BEM naming** for classes; **`data-*` attributes** as JS hooks, so styling changes don't break behaviour.
- **CSS Grid areas** let the same markup switch layouts (e.g. the breadcrumb sits above the image on mobile and in the right column on desktop).
- **Carousel** uses native horizontal scrolling with `scroll-snap`. Touch, trackpad and keyboard work without JS; JS only powers the arrows and disables them at the ends.
- **Add to cart** – the button briefly changes to "Added", the cart icon bounces and the item counter pops in. The cart is stored in `localStorage`, so the counter survives reloads and works across pages.
- **Accordion** animates height with `grid-template-rows: 0fr → 1fr`, no JS measuring.
- **Sticky header**, so the cart animation is always visible.
- **Images** are served as responsive WebP (`<picture>` + `srcset`), generated by Parcel at build time. The main product image has `fetchpriority="high"`, carousel images are lazy-loaded.

## Accessibility

- Semantic HTML: real `<form>`, `<fieldset>`, radio inputs, `<button>`s, breadcrumb `<nav>` with `aria-current`.
- `aria-expanded` / `aria-controls` on the mobile menu and accordion; collapsed panels are hidden from keyboard and screen readers.
- Screen reader announcement when a product is added to the cart (`aria-live`).
- Visible `:focus-visible` styles, `prefers-reduced-motion` respected.

## Deviations from the design

- **Contrast** – some design colors (`#a9a9a9`, `#9f938b`, muted text) don't meet WCAG AA. I kept them to match the design and would raise it with the designer.
- **Small screens** – title, feature items and button scale down below the 414px mobile design so nothing wraps or overlaps.
- **Additions** – mobile menu, hover/focus states, tablet layout and the cart counter aren't in the design.

## Alternative version (Alpine.js)

- **Products from data** – load the carousel products from JSON/API and render the cards in a loop instead of repeating the markup six times.
- **A real cart** – mini-cart drawer and cart page.
